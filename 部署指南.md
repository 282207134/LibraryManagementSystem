# 📚 部署指南

## 前置要求

- Node.js ≥ 18.x
- npm（随 Node.js 安装）
- Supabase 账号（免费：https://supabase.com）

---

## 步骤 1: 安装依赖

```bash
npm install
```

## 步骤 2: 创建 Supabase 项目

1. 访问 [Supabase Dashboard](https://app.supabase.com) 注册/登录
2. 点击 **New project** 创建项目
3. 填写项目信息，等待初始化完成（约 2-3 分钟）

## 步骤 3: 配置认证

1. 在 Supabase Dashboard 点击 **Authentication → Providers**
2. 启用 **Email** 登录
3. 开发环境建议禁用 **Enable email confirmations**

> ✅ Supabase 会自动管理 `auth.users` 表，无需手动创建

## 步骤 4: 创建数据库表

在 Supabase Dashboard 打开 **SQL Editor**，执行以下完整的 SQL 脚本：

```sql
-- 启用 UUID 扩展
CREATE EXTENSION IF NOT EXISTS pgcrypto;

-- 自动更新 updated_at 的触发器函数
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = NOW();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- =====================================================
-- 1. books 表 - 图书信息表
-- =====================================================
CREATE TABLE IF NOT EXISTS books (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  title VARCHAR(255) NOT NULL,
  author VARCHAR(255) NOT NULL,
  isbn VARCHAR(13) UNIQUE,
  publisher VARCHAR(255),
  publication_year INTEGER,
  category VARCHAR(100),
  description TEXT,
  quantity INTEGER DEFAULT 1 CHECK (quantity >= 0),
  available_quantity INTEGER DEFAULT 1 CHECK (available_quantity >= 0 AND available_quantity <= quantity),
  cover_image_url TEXT,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_books_title ON books(title);
CREATE INDEX IF NOT EXISTS idx_books_author ON books(author);
CREATE INDEX IF NOT EXISTS idx_books_category ON books(category);

CREATE TRIGGER update_books_updated_at
  BEFORE UPDATE ON books
  FOR EACH ROW
  EXECUTE FUNCTION update_updated_at_column();

ALTER TABLE books ENABLE ROW LEVEL SECURITY;

DROP POLICY IF EXISTS "Authenticated users can read books" ON books;
DROP POLICY IF EXISTS "Authenticated users can insert books" ON books;
DROP POLICY IF EXISTS "Authenticated users can update books" ON books;
DROP POLICY IF EXISTS "Authenticated users can delete books" ON books;

CREATE POLICY "Authenticated users can read books" ON books
  FOR SELECT USING (auth.role() = 'authenticated');

CREATE POLICY "Authenticated users can insert books" ON books
  FOR INSERT WITH CHECK (auth.role() = 'authenticated');

CREATE POLICY "Authenticated users can update books" ON books
  FOR UPDATE USING (auth.role() = 'authenticated');

CREATE POLICY "Authenticated users can delete books" ON books
  FOR DELETE USING (auth.role() = 'authenticated');

-- =====================================================
-- 2. users 表 - 用户扩展表（必需）
-- =====================================================
CREATE TABLE IF NOT EXISTS users (
  id UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  email VARCHAR(255) UNIQUE NOT NULL,
  full_name VARCHAR(255) NOT NULL,
  role VARCHAR(50) DEFAULT 'user' CHECK (role IN ('user', 'admin')),
  phone VARCHAR(20),
  address TEXT,
  member_since TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  max_borrow_limit INTEGER DEFAULT 5,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_users_email ON users(email);
CREATE INDEX IF NOT EXISTS idx_users_role ON users(role);

CREATE TRIGGER update_users_updated_at
  BEFORE UPDATE ON users
  FOR EACH ROW
  EXECUTE FUNCTION update_updated_at_column();

-- 创建安全定义函数，用于判断当前用户是否为管理员
-- 该函数以创建者权限执行，可绕过 RLS，避免策略递归问题
CREATE OR REPLACE FUNCTION is_admin() RETURNS BOOLEAN LANGUAGE plpgsql SECURITY DEFINER SET search_path TO public AS $$ BEGIN RETURN EXISTS (SELECT 1 FROM users WHERE id = auth.uid() AND role = 'admin'); END; $$;

ALTER TABLE users ENABLE ROW LEVEL SECURITY;

DROP POLICY IF EXISTS "Users can read own data" ON users;
DROP POLICY IF EXISTS "Users can update own data" ON users;
DROP POLICY IF EXISTS "Users can insert own data" ON users;
DROP POLICY IF EXISTS "Admins can read all users" ON users;

CREATE POLICY "Users can read own data" ON users
  FOR SELECT USING (auth.uid() = id);

CREATE POLICY "Users can update own data" ON users
  FOR UPDATE USING (auth.uid() = id);

CREATE POLICY "Users can insert own data" ON users
  FOR INSERT WITH CHECK (auth.uid() = id);

CREATE POLICY "Admins can read all users" ON users
  FOR SELECT USING (is_admin());

-- =====================================================
-- 3. borrowing_records 表 - 借阅记录表（必需）
-- =====================================================
CREATE TABLE IF NOT EXISTS borrowing_records (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  book_id UUID NOT NULL REFERENCES books(id) ON DELETE CASCADE,
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  borrowed_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  due_date TIMESTAMP WITH TIME ZONE NOT NULL,
  returned_at TIMESTAMP WITH TIME ZONE,
  status VARCHAR(50) DEFAULT 'borrowed' 
    CHECK (status IN ('borrowed', 'returned', 'overdue', 'lost')),
  notes TEXT,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_borrowing_records_user_id ON borrowing_records(user_id);
CREATE INDEX IF NOT EXISTS idx_borrowing_records_book_id ON borrowing_records(book_id);
CREATE INDEX IF NOT EXISTS idx_borrowing_records_status ON borrowing_records(status);

CREATE TRIGGER update_borrowing_records_updated_at
  BEFORE UPDATE ON borrowing_records
  FOR EACH ROW
  EXECUTE FUNCTION update_updated_at_column();

ALTER TABLE borrowing_records ENABLE ROW LEVEL SECURITY;

DROP POLICY IF EXISTS "Users can view own borrowing records" ON borrowing_records;
DROP POLICY IF EXISTS "Users can create own borrowing records" ON borrowing_records;
DROP POLICY IF EXISTS "Users can update own borrowing records" ON borrowing_records;
DROP POLICY IF EXISTS "Admins can view all borrowing records" ON borrowing_records;

CREATE POLICY "Users can view own borrowing records" ON borrowing_records
  FOR SELECT USING (auth.uid() = user_id);

CREATE POLICY "Users can create own borrowing records" ON borrowing_records
  FOR INSERT WITH CHECK (auth.uid() = user_id);

CREATE POLICY "Users can update own borrowing records" ON borrowing_records
  FOR UPDATE USING (auth.uid() = user_id);

-- 管理员可以查看所有借阅记录（使用 is_admin() 函数避免递归）
CREATE POLICY "Admins can view all borrowing records" ON borrowing_records
  FOR SELECT USING (is_admin());

-- =====================================================
-- 4. book_favorites 表 - 收藏表（必需）
-- =====================================================
CREATE TABLE IF NOT EXISTS book_favorites (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  book_id UUID NOT NULL REFERENCES books(id) ON DELETE CASCADE,
  favorited_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  UNIQUE(user_id, book_id)
);

CREATE INDEX IF NOT EXISTS idx_book_favorites_user_id ON book_favorites(user_id);
CREATE INDEX IF NOT EXISTS idx_book_favorites_book_id ON book_favorites(book_id);

ALTER TABLE book_favorites ENABLE ROW LEVEL SECURITY;

DROP POLICY IF EXISTS "Users can view own favorites" ON book_favorites;
DROP POLICY IF EXISTS "Users can create own favorites" ON book_favorites;
DROP POLICY IF EXISTS "Users can delete own favorites" ON book_favorites;

CREATE POLICY "Users can view own favorites" ON book_favorites
  FOR SELECT USING (auth.uid() = user_id);

CREATE POLICY "Users can create own favorites" ON book_favorites
  FOR INSERT WITH CHECK (auth.uid() = user_id);

CREATE POLICY "Users can delete own favorites" ON book_favorites
  FOR DELETE USING (auth.uid() = user_id);
```

> ✅ 执行成功后，所有必需的数据表都已创建完成。

## 步骤 5: 配置环境变量

### 5.1 获取 API 密钥

在 Supabase Dashboard 点击 **Settings → API**，复制：
- **Project URL**: `https://xxxxx.supabase.co`
- **anon public** 密钥

### 5.2 创建 .env 文件

在项目根目录创建 `.env` 文件：

```bash
# Windows PowerShell
New-Item -Path .env -ItemType File

# 或手动创建文件
```

### 5.3 填写环境变量

```env
VITE_SUPABASE_URL=https://your-project-id.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key-here
```

> ⚠️ 使用 `anon public` 密钥，不要使用 `service_role` 密钥

## 步骤 7: 部署到生产环境

### Vercel（推荐）

1. 将代码推送到 GitHub
2. 在 [Vercel](https://vercel.com) 导入项目
3. 配置：
   - Framework: `Vite`
   - Build Command: `npm run build`
   - Output Directory: `dist`

   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`

1. 导入 GitHub 项目
2. Build command: `npm run build`
3. Publish directory: `dist`
4. 在环境变量中添加上述两个变量

## 常见问题

### 无法连接到 Supabase
- 检查 `.env` 文件中的 URL 和 KEY 是否正确
- 确认使用的是 `anon public` 密钥
- 重启开发服务器

### 注册/登录失败
- 确认 Email 登录已启用
- 开发环境可禁用邮件确认

### 无法查看/添加图书
- 检查数据库表是否创建
- 确认 RLS 策略已配置
- 重新执行步骤 4 的 SQL

### 出现 "Could not find the table" 错误
如果控制台出现以下错误：
- `Could not find the table 'public.book_favorites'`
- `Could not find the table 'public.borrowing_records'`
- `Could not find the table 'public.users'`

**解决方案**：重新执行步骤 4 的完整 SQL 脚本，确保所有必需的表都已创建。

### 出现 500 错误或管理员界面无法打开
如果查询 `users` 表时出现 500 错误，或者访问 `http://localhost:5173/admin` 时一直显示"加载中..."：

**原因**：RLS 策略中的递归查询问题导致策略执行失败，或者用户信息加载失败。

**快速修复步骤**：

1. **打开浏览器控制台（F12）**，查看是否有错误信息
   - 查找 `加载用户信息失败` 或 `500` 错误

2. **验证 is_admin() 函数**：
   在 Supabase SQL Editor 执行：
   ```sql
   SELECT is_admin();
   ```
   - 如果报错：需要执行修复脚本
   - 如果返回 true/false：函数正常

3. **验证用户角色**：
   - 在 Supabase Dashboard → Table Editor → `users` 表
   - 确认你的用户 `role` 列是 `admin`

4. **重新执行修复脚本**：
   - **推荐**：查看 `手动输入修复步骤.md` 文件，手动输入 SQL（避免换行符丢失）
   - 或查看 `修复步骤说明.md` 文件，按照分步指南执行
   - 如果复制粘贴失败，直接在 SQL Editor 中手动输入每个关键字

5. **清除缓存并重新登录**：
   - 清除浏览器缓存（Ctrl + Shift + Delete）
   - 退出登录并重新登录
   - 再次访问 `/admin` 路径

**详细调试指南**：查看 `调试管理员界面.md` 文件，包含完整的排查步骤。

**或完整重建**：重新执行步骤 4 的完整 SQL 脚本（已包含修复后的 RLS 策略）

### 关于 auth.users.id 的说明
- `auth.users` 是 Supabase 系统自动管理的表，用于存储用户认证信息
- `public.users` 表的 `id` 字段是外键，引用 `auth.users.id`
- 这是正确的设计：`auth.users` 负责认证，`public.users` 负责扩展用户资料
- 在 Supabase Dashboard 中，`auth.users` 表位于 **Authentication → Users**，不在 Database 中直接显示

### 生产环境无法访问
- 检查部署平台的环境变量配置
- 确认构建成功
