# Examples

## 示例 1：用户说“这个页面太乱了，帮我优化”

推荐输出：

```markdown
## 目标
- 提升图书列表页的扫描效率与借阅转化

## 问题诊断
- 卡片信息密度过高，主次不分
- 主操作按钮视觉不突出
- 空状态缺少引导

## 设计方案
- 信息层级：标题 + 作者为主，库存与分类次级展示
- 布局与组件：统一卡片内边距与行高，操作区固定在底部
- 交互与状态：按钮增加 loading 与禁用；空状态提供“去搜索”
- 响应式策略：移动端单列，大屏双列
- 可访问性策略：按钮与背景对比增强，focus 样式可见

## 实施计划
1. 统一卡片结构与 spacing token
2. 重构操作区并补齐状态组件
3. 完成响应式与可访问性验收
```

## 示例 2：用户说“请按设计稿实现，并保证可访问性”

推荐行为：

1. 先识别设计稿里的组件与 token 映射（颜色、字体、间距）。
2. 优先复用现有组件，不足部分再增量扩展。
3. 为可交互元素补齐键盘操作与 focus 样式。
4. 对表单错误信息提供文本提示，不仅是红色边框。
5. 交付时附上可访问性检查结果与剩余风险。

## 示例 3：用户说“统一全站按钮风格”

推荐行为：

1. 定义按钮语义层级：primary/secondary/ghost/danger。
2. 统一尺寸体系：sm/md/lg（高度、padding、字号）。
3. 统一状态：default/hover/active/focus/disabled/loading。
4. 批量替换页面中的非标准按钮样式。
5. 在 PR 中说明视觉与交互一致性收益。
